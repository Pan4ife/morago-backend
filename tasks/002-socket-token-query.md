## Цель
Браузер не умеет ставить заголовок `Authorization` при WebSocket-подключении Socket.IO. Сервер сигналинга
должен принимать access-токен и из параметра адреса `?token=<jwt>`, если заголовка нет. Остальные проверки
токена (подпись, тип access, пользователь существует и не BLOCKED) работают одинаково для обоих способов.

## Контекст
- `src/main/groovy/org/morago/config/JwtAuthorizationListener.java` — сейчас читает только заголовок.
- `HandshakeData.getSingleUrlParam("token")` у netty-socketio отдаёт параметр адреса.
- Контракт событий: `docs/socketio-events.md`, раздел «Подключение».

## Критерии приёмки (проверяют автомат и судья)
1. Есть unit-тест `JwtAuthorizationListenerTest` (Mockito, без Spring и базы), он зелёный.
2. Тест проверяет: валидный токен в заголовке — пускает и кладёт userId; валидный токен в `?token=` без заголовка —
   пускает и кладёт userId; нет ни заголовка, ни параметра — отказ; refresh-токен в `?token=` — отказ;
   пользователь BLOCKED с токеном в `?token=` — отказ.
3. Если есть и заголовок, и параметр — используется заголовок.
4. Остальное поведение слушателя не изменилось, новых красных тестов нет.

## Чек-лист для глаз (проверяет человек)
- [ ] Логика проверки токена не продублирована для двух способов — сначала достаём токен, потом одна проверка.
